## Plan Summary
# Plan: build-loop pre-flight checks for broken test commands (#6987)

## The main design decision

The pre-flight check can't just run the test command and look at the exit code. When the loop starts, the tests are **supposed** to fail, because the feature hasn't been written yet. A failing `npm test` at that point is normal. It would also cost a lot: `metrics.json` shows the test stage takes about 1,365s.

So the check separates two cases:

- **The command itself is broken:** a syntax error, an executable that doesn't exist, a missing npm script, npm's default `"no test specified"` placeholder, or a missing Makefile.
- **The tests fail:** that's expected, and the loop proceeds as usual.

It does this with static checks and never runs the test suite.

**Scope.** `sw-loop.sh` has no separate lint command. The commands it runs are `TEST_CMD`, `FAST_TEST_CMD` and `ADDITIONAL_TEST_CMDS` (see `run_test_gate`, `scripts/sw-loop.sh:997`). The check covers exactly those. Full environment validation stays in #6428.
