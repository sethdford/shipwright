# Plan: Budget-aware pipeline template selection (#6924)

## What exists today

- **Template resolution** (`scripts/lib/pipeline-commands.sh:711-715`): `PIPELINE_NAME` defaults to `standard`. `generate_reasoning_trace` may export `PIPELINE_TEMPLATE`, and that replaces the name only when `PIPELINE_NAME == "standard"`. The code can't tell `--template standard` apart from "no flag", so today Thompson sampling can override an explicit `--template standard`. That breaks acceptance criterion 3.
- **Flag parsing** (`scripts/lib/pipeline-cli.sh:140`): `--pipeline|--template) PIPELINE_NAME="$2"`. Nothing records that the user set it.
- **Daemon** (`scripts/lib/daemon-dispatch.sh:230`): always passes `--pipeline "${PIPELINE_TEMPLATE:-standard}"`. If only the pipeline side checked the budget, it would see every daemon run as explicit and never downgrade. The daemon therefore has to apply the check itself before it builds the args.
- **Budget source** (`scripts/sw-cost.sh remaining-budget` → `cost_remaining_budget`): prints a number such as `3.42` (possibly negative) or `unlimited`. On the JSON fallback path it first prints an `info` line to **stdout** ("▸ Budget not configured…"), so callers must take `tail -1` and check that it's a number.
- **Config helper**: `_smart_int <key> <default>` in `scripts/lib/compat.sh:385`. It checks the env var `SW_<KEY>`, then `daemon-config.json` `getpath`, then the default. It returns the raw string, so decimal values like `7.5` come through unchanged.
- **Templates** (`templates/pipelines/`), by number of enabled stages: full 15, enterprise 14, deployed 14, autonomous 13, standard 11, tdd 11, cost-aware 10, fast 6, hotfix 6.

## Brainstorming and alternatives

**Minimum change that meets the criteria:** one small library function that takes a template name and an "explicit?" flag and returns the final template. It is called at two places: pipeline start and daemon spawn. It emits one event.

## Specification: Budget-aware pipeline template selection

### Goals
- - Pipeline start checks remaining daily budget before selecting/confirming a template when no `--template` is explicitly forced
- - Below a configurable budget threshold (daemon-config.json), template is auto-downgraded one tier and the decision is logged/emitted as an event
- - Explicit `--template` flag always wins over budget-based auto-selection
- - Test suite covers: low-budget downgrade, explicit override, and normal-budget no-op paths
