- **The bug, at `scripts/sw-hygiene.sh:449`:**
  `hardcoded_count=$(grep -rE "hardcoded|Hardcoded|HARDCODED" "$scripts_dir" --include="*.sh" | wc -l)`
  This counts the English word, mostly in comments and test names (for example `sw-adapters-test.sh:186 "No hardcoded user paths"`, `sw-agi-roadmap-test.sh:749`). It currently returns **49**.
- **The same word is also in the findings grep, `sw-hygiene.sh:464`.** So `findings_sample` is also full of comment hits.
- **Who reads `counts.hardcoded`:** `sw-doctor.sh:1584` (display only) and `sw-strategic.sh:417`. The strategic agent's prompt says "suggest … reduce-hardcoding issues", so a bad count leads to bad strategic issues. That is how this issue was created.
- **Issue #5469 describes this exact defect.** Its suggested fix: count integers in threshold position, skip exit codes, indices, `cut -c` and widths, and keep the word count as a separately named counter.
- **Prototype run on this repo:** the regex `-(lt|gt|ge|le|eq|ne)[[:space:]]+"?([2-9]|[1-9][0-9]+)([^0-9.]|$)`, with comment lines and `*-test.sh` excluded, finds **560** lines. That includes the literals #5469 expected in `lib/session-restart.sh` (`:215 -ge 3`, `:350 -ge 3`, `:398 -gt 5`, `:403 -ge 2`) and `lib/loop-restart.sh:176 -lt 3`. It also catches exit-code comparisons that must be removed: `sw-test-all.sh:121 $rc -eq 137`, `sw-e2e-orchestrator.sh:348 $exit_code -eq 124`.
- **Two portability traps found while prototyping:**
  1. A pattern that starts with `-` is read as an option. It must be passed with `grep -E -e`.
  2. `\b` is not portable to BSD grep on macOS CI. Use `([^0-9.]|$)` instead.
- **Fixture tests aren't possible yet:** `REPO_DIR` is fixed at `sw-hygiene.sh:11`, so there's no way to point the scanner at a test repo.
